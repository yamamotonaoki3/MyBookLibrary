# MyBookLibrary 要件定義書

## 1. アプリ概要

文学賞の受賞・ノミネート作品の読書進捗管理と、お気に入り著者の管理を行う Web アプリケーション。複数のユーザーが利用できる（ユーザー登録・ログイン機能あり）。

## 3. 機能要件（実装済み）

### 3.1 認証・アカウント管理

- メールアドレス＋パスワードでユーザー登録・ログインができる
- Google アカウントでログイン（OAuth）できる
- パスワードを忘れた場合、メールアドレスを確認してパスワードを直接再設定できる（メール送信なし）
- ログイン失敗を 10 回繰り返すとアカウントが 15 分間ロックされる
- ロック中はログイン試行残回数を画面に表示する
- ロール管理：一般ユーザー（`user`）と管理者（`admin`）を区別する
- 自分のアカウントを削除できる（一般ユーザーのみ。管理者ロールは削除不可）
- 削除時は関連する全データ（レビュー・いいね・通報・通知・読書ステータス・お気に入り著者・セッション・アカウント）をトランザクションで一括削除する
- 設定画面（`/settings`）でアカウント情報（名前・メールアドレス・ロール）を確認できる

### 3.2 読書ステータス管理

- 本ごとに以下の4状態でステータスを記録できる
  - `unread`（未読）
  - `want_to_read`（読みたい）
  - `reading`（読書中）
  - `read`（読了）
- ステータスは何度でも変更できる（upsert）
- `unread` に戻すとレコードが削除される（デフォルト状態 = レコードなし）

### 3.3 本の一覧・検索

- マイ本一覧画面でステータス別・著者別に絞り込み表示できる
- 楽天ブックス API を使って書籍を検索し、読書ステータスに追加できる
- 検索結果は単行本優先（単行本 > 新書 > 文庫 > その他）・最古出版年でタイトル重複を除外する
- ISBN で直接書籍の詳細ページへ遷移できる
- カメラでバーコードをスキャンして ISBN を読み取り、書籍を検索できる（フォールバック：国立国会図書館 API）
- 読書ステータス追加時、同タイトル・同著者の本が既にDBに登録済みの場合は版違い（単行本/文庫など）でも既存レコードに紐付ける（重複登録防止）

### 3.4 受賞・ノミネート作品一覧・読書進捗管理

- 賞ごとに受賞作品・ノミネート作品の両方を一覧表示する
- 受賞作品とノミネート作品をバッジで視覚的に区別する
- 年度フィルターで絞り込みができる
- 各作品に読書ステータスを設定できる
- 賞全体の読了率をプログレスバーで確認できる

### 3.5 お気に入り著者管理

- 著者を「お気に入り」として登録・削除できる
- お気に入り著者の一覧を表示する
- 著者ごとに新刊通知の ON/OFF を切り替えられる
- 著者名をクリックするとその著者の書籍一覧を表示する
- 書籍ごとに読書ステータスを変更できる
- 楽天ブックス API（フォールバック：国立国会図書館 API）で著者名を検索して登録できる

### 3.6 感想投稿・一覧

- 本ごとに感想（レビュー）を投稿できる（10〜2000 文字）
- ネタバレあり／なしのフラグを付けられる
- 自分の感想を編集・削除できる
- マイレビュー画面で自分の投稿一覧を確認できる
- 本の詳細画面で全ユーザーの感想を閲覧できる

### 3.7 いいね・通報

- 他のユーザーの感想にいいねができる（1ユーザー1いいね）
- いいねを取り消すことができる
- 不適切な感想を通報できる（1ユーザー1通報）

### 3.8 通知

- 通知の種類は以下の2種類
  - **新刊通知**：お気に入り著者が新刊を出した際（通知 ON の著者のみ）
  - **いいね通知**：自分の感想にいいねが付いた際
- 通知を個別に既読にできる
- 全通知を一括で既読にできる
- 次回ログイン時またはアプリ表示時に未読通知件数を確認できる
- PWA インストール時はアプリアイコンに未読通知数をバッジ表示できる（Browser Badge API）

### 3.9 管理者機能

- 書籍タイトルを入力して楽天ブックス API から書籍情報を自動取得し、受賞／ノミネート登録ができる
- 書籍検索に国立国会図書館（NDL）SRU API モードを追加。絶版・旧版など楽天に存在しない書籍のISBNを検索できる
- 管理者画面から直接書籍の ISBN を編集できる
- 近隣図書館の登録・削除ができる（管理者アカウントは設定画面がないため管理者パネルから設定する）
- 受賞登録の編集・削除ができる
- CSV ファイルで受賞・ノミネートデータを一括インポートできる
- 通報されたレビューの一覧を確認し、削除できる
- ダッシュボードでユーザー数・当月新規ユーザー数・レビュー数・いいね数の統計を確認できる
- ユーザー一覧を確認し、一般ユーザーを削除できる（自身・他の管理者は削除不可）
- ユーザー削除時は関連する全データ（レビュー・いいね・通報・通知・読書ステータス・お気に入り著者・セッション・アカウント）をトランザクションで一括削除する
- お問い合わせ一覧を確認し、ステータス（open/closed）を更新・削除できる

### 3.10 新刊チェック（Cron）

- 定期実行（AWS EventBridge Scheduler + Lambda）でお気に入り著者の新刊（1週間以内）を楽天ブックス API で検索する
- 新刊が見つかった場合、通知 ON のユーザーに通知を作成する
- 同じ新刊で重複通知は作成しない

### 3.11 お問い合わせ

- お問い合わせフォームからカテゴリ・件名・本文を入力して送信できる
- カテゴリは「一般」「バグ報告」「機能要望」「アカウント」「その他」の5種類
- 送信済みのお問い合わせは `ContactInquiry` として保存される
- ログインユーザーの名前・メールアドレスはフォームに自動入力される

## 4. 将来実装予定機能

### 4.1 著者ベースのおすすめ機能

- 同じ著者をお気に入り登録している他ユーザーのデータを参照する
- 「この著者を登録しているユーザーはこの著者も読んでいます」という形でおすすめを表示する
- 協調フィルタリング的なアプローチ（著者単位）

### 3.12 近隣図書館の在庫確認（実装済み）

- ユーザーが近くの図書館を最大 5 館まで登録できる（設定画面 `/settings` または管理者パネル `/admin`）
- 本一覧・本を探す・著者別書籍一覧・賞別作品一覧の各画面で「図書館の在庫を確認」ボタンを表示する
- カーリル API を使い、登録した図書館の貸出状況（貸出可 / 貸出中 / 蔵書なし）をリアルタイムで確認できる
- 貸出状況のバッジから図書館の予約ページへ直接遷移できる（外部サイト）
- ISBN のない書籍は在庫確認不可（バッジ非表示）
- カーリル API はポーリング方式のため、結果取得まで最大数秒かかる場合がある

## 5. 非機能要件

### パフォーマンス

- ページ表示：3秒以内
- API 応答：1秒以内

### セキュリティ

- パスワードのハッシュ化（bcryptjs、salt: 12）
- HTTPS 通信（AWS CloudFront が対応）
- SQL インジェクション対策（Prisma ORM が対応）
- 不正ログイン対策（10回失敗で 15 分ロック）
- Cron エンドポイントを Bearer トークンで保護

### ユーザビリティ

- スマホ・PC 両対応（レスポンシブデザイン）
- 日本語のみ対応
- PWA 対応（ホーム画面へのインストール、スタンドアロン起動）

### 保守性

- Zod によるリクエストバリデーション
- Jest によるユニットテスト（バリデーション・ユーティリティ・API ルート）
- 楽天ブックス API の 429 エラー時にリトライ処理を実装

### 監視

- AWS CloudWatch でエラーアラート・アクセス数・パフォーマンスを監視する

## 9. 認証フロー

### Credentials 認証

1. メールアドレス＋パスワードで認証
2. ログイン失敗時：`loginFailCount` をインクリメント
3. 10 回失敗で `lockedUntil` を現在時刻 + 15 分に設定
4. ロック中はログイン不可（残り試行回数を `/api/auth/remaining-attempts` で取得可能）
5. パスワードリセット成功時に `loginFailCount` と `lockedUntil` をリセット

### Google OAuth

1. Google アカウントでログイン → `Account` テーブルに OAuth 情報を保存
2. Google アカウントユーザーはパスワードリセット不可（`GOOGLE_ACCOUNT` エラーを返す）

### セッション

- JWT ストラテジー（`strategy: "jwt"`）
- トークンにユーザー ID（String 型）とロールを含める
- `/admin` パスへのアクセスは `role === "admin"` チェック
