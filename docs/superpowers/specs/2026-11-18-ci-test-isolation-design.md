# CI test isolation design — #852

## Outcome and approval boundary
Use the existing Docker toolchain to prevent app test/build execution from reaching production, demo, Pages, external APIs/DBs or Cloudflare. The user approved the minimum approach: suppress known usage reporting, remote fonts and test links; isolate app test/build steps only; preserve preparation/static checks and every existing suite. This branch covers local implementation, validation and review. Commit/push/PR/merge/publication need separate delivery approval.

## Existing behavior and scope
CI currently runs `test`, `integration-d1`, `worker` for pull requests and main pushes. MySQL is local port3307/test DB; E2E uses app3100/PWA3200 and stub3999; Worker smoke uses8788. Guards and stub env express intent but do not deny every native/SW/child-process connection. PR848 and the separate #849 README branch stay untouched.

## Chosen design
1. Keep checkout, Node22 setup, npm/browser/image acquisition, Prisma client generation, pure schema:d1:check, docs/type/lint checks, GitHub control and artifact upload outside the restricted runtime. Preparation may fetch required dependencies but does not run app tests/build or app code. Use a clean source snapshot for preparation so old app/.env.local is not read. Current package postinstall only generates the MySQL and D1 Prisma clients; this is a bounded CI safety change, not a defense against arbitrary malicious PR code. The d1:migration:check execution (temporary SQLite applies every migration and invokes Prisma) stays in the restricted test suite, preserving its original test-job responsibility/result. Test commands, test-owned SQLite/MySQL migrations, app-producing builds, browser/server/workerd execution run only inside the restricted runtime.
2. Host orchestration creates run-owned containers with unique names/labels. The MySQL container has `--network none`, port3307, a fresh tmpfs datastore and dummy test credentials. The app runtime joins that container's network namespace, so app/browser/DB/stub communicate through loopback only. Readiness requires authenticated TCP SELECT 1 at 127.0.0.1:3307 using the test user/test DB, never the initialization socket or a socket-only ping. D1/Worker suites need no MySQL and use their own `--network none` app runtime.
3. No published HostConfig.PortBindings, host network, host bind mounts, Docker socket, foreign/existing DB volumes, real env files, host home or credentials enter the runtime. Image EXPOSE metadata is allowed; a run-owned /var/lib/mysql tmpfs is the intentional DB mount exception. CI source uses explicit tracked checkout paths. Local uncommitted validation uses those tracked paths plus the exact approved new-file allowlist for this plan; include the new runner/tests/spec/plan without staging or committing. Canonicalize paths inside the designated worktree, reject source symlink/junction root escapes, real env/private-agent overlays/host metadata, and verify per-file SHA256 against the approved input manifest before app execution. Arbitrary untracked paths/globs are never included. Preserve dependency .bin/vendor internal links required by installed packages; do not confuse those with source-root escapes. Copy only these verified source paths, compatible prepared Linux dependencies, required generated clients/browser artifacts and a Node22 binary matching preparation. Create the minimal Git index needed by existing checks without copying original .git/remotes.
4. Use the version-locked Playwright1.62.1 noble runtime image for browser/shared-library availability (prepared immutable amd64 digest c091b21d9fae78c76e85cd4356431e9b018402f172a214fc7d7a5e9a7e29d8ac). Use exact Node22.23.4 Linux x64 from its verified official tar, ABI127/npm10.9.9, never Windows node.exe or Alpine/musl artifacts. Match npm and child-Node PATH to that same toolchain; verify architecture, glibc/native dependency/workerd/Chromium execution before app commands. The image may supply the browser revision/OS libraries directly after preflight; do not duplicate a full host browser/apt install and transfer unnecessarily. Non-browser suites may reuse that runtime to avoid another image/OS recipe. Pull/resolve images outside restricted execution; create/run use resolved immutable image IDs and never pull. Ops must confirm runtime compatibility before the full matrix; incompatibility is a stop-and-adjust condition, not permission to execute on host.
5. An allowlisted suite maps to fixed in-repo commands. No arbitrary caller command, env passthrough, destination or Docker options. The host runner validates ownership/isolation from inspect, stages input, runs the fixed suite, copies bounded artifacts and removes only resources it created with matching ownership. Preserve a nonzero primary suite exit even if artifact/cleanup also fail. If the suite succeeded, failure of required artifact collection or cleanup fails the job. Partial setup and SIGINT/SIGTERM/Actions cancellation clean up only created container IDs whose ownership labels match. Use local finally plus signal handling; hard kill/runner disappearance can prevent final cleanup and must be reported as a limit. Fixed run-owned artifact output directories cannot copy/upload links outside their bounds. Runtime CI=true is fixed so forbidOnly/retries/server-reuse match existing CI.
6. Reuse existing font mock for CI Worker build only, disable Wrangler metrics/error reports and Next telemetry for CI, make ordinary E2E reservation targets use the local reserve stub through an explicit ordinary webServer opt-in, keeping the stub constructor default unchanged. The existing ordinary library-availability.spec.ts path must assert href localhost:3999/stub/reserve and local HTML200; browser-protection.spec.ts route.fulfill alone is not this regression. Keep PWA serviceWorkers allow, cache assertions and all existing tests. Do not add a universal monkeypatch firewall.

## Files and responsibilities
- `.github/workflows/ci.yml`: preserve three job names, outside preparation/static stages, restricted test/build stages and always-uploaded artifacts.
- `app/scripts/ci-isolation.mjs`: host runner/policy, input packaging, Docker adapter and lifecycle/ownership checks.
- `app/scripts/ci-isolation.test.mjs`: pure policy/orchestration regressions with a fake Docker boundary; no Docker launches from tests.
- `app/scripts/ci-isolated-suite.mjs`: fixed commands inside runtime, loopback/test-env preflight, sequential suite exit handling.
- `app/e2e/stub-server.ts` plus ordinary Playwright env/fixture as needed: local reservation path with existing semantics; PWA behavior retained.
- `app/package.json`: focused runner test entry if needed; no new dependency/lock changes.
- `docs/test-dependency-map.md`, `docs/test-plan.md`: preparation/runtime boundary, complete matrix, evidence and bootstrap sequence.
- This spec and its implementation plan.

## Validation and safety acceptance
- TDD must show meaningful RED then GREEN for rejected unsafe inputs, non-none namespace/foreign owner rejection, command/secret injection exclusion, primary failure propagation and owned-only cleanup. Do not add tests merely restating config strings.
- Ops alone runs Docker and all app tests in safe containers; the implementation owner performs source edits/static checks only.
- Full matrix retains Jest+coverage, integration MySQL, ordinary/cron/demo/PWA E2E, D1 integration, Worker build/dry-run-size/config checks/local smoke, existing type/lint/docs/schema checks and runner regressions. No skips or unjustified timeout changes.
- Runtime inspect: none namespace/loopback, no published HostConfig.PortBindings, host binds/foreign volumes, privileged mode or NET_ADMIN; allow image EXPOSE and the owned DB tmpfs, explicit env keys, fresh DB state; assert that local new-file allowlist/manifest hashes match the actual copied input. Capture source/dependency/runtime version fingerprints, exit codes, artifacts and stopped resource state. Do not probe real prohibited endpoints.
- CI introduction is checked statically before any delivery: workflow is `pull_request` (not pull_request_target), so the proposed PR merge ref includes the changed workflow; inspect the complete workflow set and initial-event behavior before creating/updating PRs. No bypass of required checks.
- Existing root six protected paths and #847/#849 source/index hashes remain stable.

## Deliberate limits / stop conditions
No new dependency, technology, host firewall, product behavior, README or media changes. Docker --internal alone is insufficient because host/gateway access can remain. Full E2E/Worker operation in the new runtime is not yet proven by earlier offline npmcheck. If runtime transfer or lifecycle requires broad redesign, stop and report evidence to the root before expanding scope.

Implementation boundary: the reviewed pure mechanisms remain in ci-isolation.mjs and ci-isolated-suite.mjs. Focused entry points run-ci-isolated.mjs (host Docker/input/artifact adapter) and run-ci-isolated-suite.mjs (restricted preflight/command executor) keep those modules side-effect-free when imported. Linux dependency input also includes current-schema MySQL/D1 generated clients with source-schema SHA provenance.
