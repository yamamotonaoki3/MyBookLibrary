# デモ環境の方針と構成

README の「ライブデモ」を再開するための、デモ専用環境の方針をまとめる（親 Issue #609、本文書は #717）。
構築・投入・保護・公開は、続く Issue（#718〜#723）で行う。

## 目的と前提

- 誰でも触れる**ライブデモ**を、Cloudflare Workers + D1 で公開する。
- ステージングは**兼用しない**。疎通確認（`smoke:remote`）・E2E への影響と、デモが荒らされたときの影響を、互いに及ぼさないため。
- 本番の利用者向けデータ（ユーザー、レビュー、メールアドレスなど）は、**一切持ち込まない**。

## 構成

| 項目 | 内容 |
| --- | --- |
| Worker | `mybooklibrary-demo`（`wrangler.jsonc` の `env.demo`。公開 URL は `https://mybooklibrary-demo.nyproducts.workers.dev`） |
| D1 | `mybooklibrary-demo-db`（本番・ステージングとは別の D1） |
| Cron | 毎日 UTC 18:00（JST 03:00）にデモのデータの初期化だけを行う（新刊チェックは動かさない。下の「初期化」） |
| 自動デプロイ | Workers Builds。デプロイ元は **`demo` ブランチ**（下記） |
| マイグレーション | 本番・ステージングと同じ `prisma/d1/migrations` を、デプロイ時に適用する |
| secret | `AUTH_SECRET` などを `--env demo` で個別に登録する。`AUTH_SECRET`・`CRON_SECRET` は、本番・ステージングと**同じ値を使い回さない**（楽天の認証情報は、同じアプリを許可ドメインの追加で共用する）。値はこの文書に書かない |
| 外部 API | 楽天ブックス API の許可ドメインは、デモ Worker のドメインを追加登録するか、デモでは外部検索を使わない構成にする（#718 で決める） |

`wrangler` の環境では、バインディングと vars が継承されない。`env.demo` には、D1・`version_metadata`・vars・`triggers` をすべて明記する（ステージングと同じ書き方）。

### デプロイ元のブランチ

- `main` → ステージング、`production` → 本番、**`demo` → デモ**とする。
- `main` に直接追従させない。作りかけの変更が、公開中のデモに出るのを避けるため。
- `demo` の更新は、`main` の確認済みの時点を指して行う（`git push origin origin/main:demo`）。本番の `production` と同じ運用。

## データ方針

| 種類 | 方針 |
| --- | --- |
| 賞・本・著者・受賞（マスターデータ） | **本番のダンプ**から投入する（#719）。ダンプは暗号化したままで、リポジトリには**入れない** |
| 楽天ブックス API 由来の書誌情報 | 再配布にならないよう、リポジトリには含めない。デモ用 D1 への投入のみ |
| ユーザー・関係・投稿 | **すべて架空**。`demo_` を付けた名前と `@example.com` のメールで、フォロー・読書状況・レビュー・いいね・通報・通知・お気に入り著者・ライブラリを用意する（#720） |
| 本の登録者（`created_by` 相当） | 本番のユーザーとの対応が残らないよう、投入時に空にする |

- 投入と初期化のスクリプトは、**接続先がデモ用 D1 であること**を確かめてから動かす。本番・ステージングの名前や ID を指定したら止める。
- 実データを含むファイル（復号したダンプ）は、作業後に必ず削除する。扱いは [d1-rehearsal-runbook.md](d1-rehearsal-runbook.md) と同じ。

## 公開範囲

- **管理者アカウントは公開しない。** 管理者機能は、GIF・スクリーンショットで README に載せる（#723）。
- 公開するのは**一般ユーザーのデモアカウント**だけ。IDとパスワードは README に載せる。デモ専用の値で、本番・他サービスと共通にしない。
- README と画面に、次の注意書きを入れる。
  - 共有のデモ環境であり、**投稿やデータは、予告なく初期化される**。
  - **個人情報・実在のメールアドレスを入力しない**。
  - デモ用であり、機能の一部が制限されている。

## 保護

デモアカウントは誰でも使えるため、環境変数 `DEMO_MODE`（`"true"` のときだけ有効）で、次を制限する（#721）。`DEMO_MODE` は、`wrangler.jsonc` の `env.demo` の vars だけに書く。本番・ステージングには書かない（CI で、本番・ステージングの設定に入っていないことと、デモの設定に入っていることを確認している）。

| 対象 | デモ環境での扱い |
| --- | --- |
| パスワード変更、合言葉の変更、パスワードの再設定 | API は 403（`code: "DEMO_MODE"`）。設定画面は、合言葉の欄を出さず、パスワード変更の画面は案内だけ。再設定の画面も案内だけ |
| メールアドレスの変更 | この機能は、もともとない |
| 退会（アカウント削除） | API は 403。設定画面に、削除の欄を出さない |
| 新規登録 | **禁止**（API は 403。画面は案内だけ）。公開のデモアカウントで足りるうえ、実在のメールアドレス・氏名が、デモの DB に入るのを避けるため |
| 問い合わせの送信 | 禁止（API は 403）。本文に個人情報が入り得るため |
| Google ログイン | 登録しない。ログイン・登録の画面のボタンも出さない |
| 管理者向けの操作 | 管理者の API は、すべて 403（`requireAdminSession` で共通に拒否）。管理画面（`/admin`）は、開かずにトップへ戻す |
| ログイン状態の放置 | セッションの有効期間を **15 分**にする（`DEMO_MODE` のときだけ。`src/lib/sessionPolicy.ts`、#736）。ページの移動などでセッションが更新されるたびに延び、15 分更新がなければ、次のリクエストで再ログインが必要になる。本番・ステージングは、保持ありが 30 日、保持なしが 8 時間（#737。[認証の定義書](features/auth.md)） |
| 画面 | ページの上部に、「デモ環境です。個人情報は入力しないでください。データは予告なく初期化されます。」を出す。ログイン画面に、デモアカウントの案内を出す |

無効（`DEMO_MODE` が未設定など）のときは、従来どおり動く（単体テスト・E2E で確認している。E2E は `npm run test:e2e:demo`）。

## 初期化

- 架空データは、**識別子（`demo_` と `@example.com`）だけを条件**に削除・再作成する。マスターデータ（賞・本・著者）には触れない（#720、#721）。
- 初期化は、スクリプトの手動実行と、Cron の両方で行える。Cron は、毎日 UTC 18:00（JST 03:00）に、`GET /api/cron/reset-demo`（Bearer 認証、`DEMO_MODE` のときだけ動く）を呼ぶ。デモでは、新刊チェックの Cron は動かさない。既存の管理者（`demo_admin`）は消さない。
- 消えるのは、`demo_` のユーザー自身、そのユーザーが持つデータ、デモのレビューに付いた他のユーザーのいいね・通報（レビューを作り直すため）。デモ以外のユーザーが、デモのユーザーをフォローする関係や、デモ以外のユーザー宛ての通知は、消さない。
- 手動実行と Cron を、同時に実行しない（D1 には、排他の仕組みがない）。手動で実行するのは、Cron の時刻（JST 03:00 前後）を避ける。
- 初期化の後に、件数が想定と一致することを確かめる。

## 架空のユーザーと関係のデータの作成・初期化（#720）

`app/` で実行する。接続先は、デモの D1（名前と ID の両方が一致するリモート）か、ローカルの D1 だけ。本番・ステージングは、接続の前に拒否する。先に、マスターデータの投入（[migration の README](../app/prisma/scripts/migration/README.md) の「デモ用 D1 へのマスターデータの投入」）が必要。

```bash
npm run demo:seed -- status --remote --d1-name mybooklibrary-demo-db --d1-id <デモの D1 の ID>        # 件数の確認（読み取りのみ）
npm run demo:seed -- seed   --remote --d1-name mybooklibrary-demo-db --d1-id <デモの D1 の ID> --yes  # 作成（何度実行しても同じ結果）
npm run demo:seed -- reset  --remote --d1-name mybooklibrary-demo-db --d1-id <デモの D1 の ID> --yes  # デモのユーザーとデータだけを削除
```

- 一般ユーザーは 8 名（`demo_sakura` など。メールは `demo_<名前>@example.com`）。パスワードは、公開してよいデモ用の固定値（`DEMO_USER_PASSWORD`。README に載せる）。
- 管理者（`demo_admin`）は、環境変数 `DEMO_ADMIN_PASSWORD`（12 文字以上）を設定して実行したときだけ作る。値は、コード・出力・リポジトリに書かない。設定しなければ作らない。
- 関係: フォロー（相互フォローを含む）、読書状況（読了・読書中・読みたい）、レビュー（ネタバレあり・なし、非公開を含む）、いいね、通報、通知、お気に入り著者、図書館。「未読」は、アプリの仕様で、読書状況の行がない状態のため、行は作らない。
- 本は、賞のある本を ID の昇順に選ぶ（ID は決め打ちしない）。
- 削除の対象は、名前が `demo_` で始まり、メールが `@example.com` で終わるユーザーと、そのユーザーが持つデータだけ。疎通確認用のユーザー、マスターデータ（賞・本・著者）には触れない。
- 楽天 API の確認: `npm run smoke:demo-rakuten`（デモの一般ユーザーでログインし、検索 API が楽天ブックスの結果を返すことだけを確認する）。
